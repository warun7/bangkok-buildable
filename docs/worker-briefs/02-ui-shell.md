# Worker brief 02: UI shell, map and drawing (React + MapLibre + deck.gl + terra-draw)

You are one worker in a small team building a browser tool for Bangkok real-estate developers. The user draws a plot on a map, marks which edges face a road and how wide the road is, picks a building type, and sees: the zoning rules that apply, the 3D space the building may fill (the "envelope"), and 2–3 concept designs with a pass/fail checklist each, all in 3D among the real surrounding buildings. Everything updates live, with no reload. It must look like something you could put in front of a client: calm, precise, architectural.

Another worker is writing the geometry engine in `src/engine/geom/*` and `src/engine/envelope.ts`; the orchestrator writes `src/engine/rules*`, `src/engine/design/*` and `src/engine/analyze.ts`. Do not touch those, `src/engine/types.ts`, `package.json`, the lockfile or any config. Do not install packages, deploy, push or git commit. Read `src/engine/types.ts` first: your components consume `Analysis`, `Design`, `AppliedRule`, `Check`, `Envelope` exactly as defined there.

Installed: react 19, maplibre-gl 5.24 (NOT 6: deck.gl interleaving breaks on 6), @deck.gl/core|layers|mapbox|mesh-layers 9.4, terra-draw 1.39 + terra-draw-maplibre-gl-adapter 1.5, earcut. Import maplibre as `import * as maplibregl from "maplibre-gl"` (no default export). Plain CSS (CSS modules or one stylesheet), no CSS framework.

## Your files
- `src/ui/**` (components), `src/map/**` (map setup, style, layers, road detection), `src/styles/**`, `src/fixtures/**` (mock data), and `src/App.tsx` (temporary: you own it during this task; render the shell with fixture data so it can be seen working. The orchestrator will wire the real engine afterwards, so keep the data flow in one place: `App` holds the inputs state and calls a single `analyze(input): Analysis` function, which for now you import from `src/fixtures/mockAnalyze.ts`).

## What to build
1. **Layout** (desktop first, works down to 1280×720; mobile not required but must not break): full-bleed 3D map; a left panel (~360 px) for inputs; a right panel (~400 px) for results; a slim top bar with product name "Bangkok Buildable", the zone badge (from `analysis.zone`), and a small "About / sources" link that opens a modal (placeholder text is fine). Panels scroll independently; the map stays visible.
2. **Map** (`src/map/`): MapLibre with OpenFreeMap vector tiles. Start from `https://tiles.openfreemap.org/styles/liberty`, but restyle at load for a calm architectural look: hide POI icons and most labels except road names and place names, keep the 3D building extrusions (`building-3d` layer, uses `render_height`/`render_min_height`) in a light neutral grey with slight transparency, roads white/light grey, water soft blue. A toggle for satellite imagery (Esri World Imagery raster tiles `https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`, with attribution "Esri, Maxar, Earthstar Geographics"), inserted below roads. Initial view: Asok/Sukhumvit, Bangkok (100.5605, 13.7385), zoom 17.5, pitch 55. Fit to the plot when one is loaded.
3. **Plot drawing** with terra-draw (polygon mode, then select mode with draggable vertices, midpoints to insert vertices, and vertex deletion). Buttons: "Draw plot", "Edit", "Clear", plus a "Sample plots" menu from `src/fixtures/samplePlots.ts` (create 3 realistic non-rectangular plots near Sukhumvit: an irregular 5-sided plot on a narrow soi, a corner plot between a main road and a soi, and a deep L-shaped plot; coordinates as [lng, lat]; label each with a name). Every vertex drag must update the analysis live (throttle with requestAnimationFrame, not debounce-with-delay). Show edge lengths and the plot area live. Hide the existing OSM buildings that sit inside the plot (filter by feature id if available, otherwise draw a ground-level plot fill and accept overlap; explain what you did).
4. **Road frontage** (`src/map/roads.ts`): `detectFrontages(map, plot: LngLat[]): FrontageCandidate[]` using `map.querySourceFeatures` on the OpenMapTiles `transportation` (+ `transportation_name` for names) source-layers: for each plot edge, find road lines within ~20 m of the edge midpoint that run roughly parallel (within 30°). Suggested right-of-way width by class when no better data: motorway/trunk 40, primary 30, secondary 20, tertiary 14, minor/residential/service 8, path 4 (put these in one exported table, documented as estimates). In the left panel list the plot edges as "Edge A, B, C…" with length; each edge has a "faces road" toggle, the road name, and a width input (number + slider, 3–60 m) defaulting to the suggestion. Clicking an edge on the map toggles it too. Draw each frontage on the map: the plot edge highlighted, and the far side of the road as a dashed line offset outward by the width (this is the line the height rule measures from).
5. **Building type** selector: Condominium, Office, Hotel (ids from `BuildingTypeId`).
6. **3D layers** (`src/map/layers.ts`, deck.gl via `MapboxOverlay({ interleaved: true })`, all geometry in local metres with `coordinateSystem: COORDINATE_SYSTEM.METER_OFFSETS` and `coordinateOrigin: [...analysis.origin, 0]`):
   - plot outline on the ground (strong line) and a subtle fill;
   - envelope: `analysis.envelopes.highrise ?? analysis.envelopes.lowrise` mesh as a translucent volume (`SimpleMeshLayer` with a custom mesh built from `positions/normals/indices`, or a custom approach), plus its `edges` as crisp lines (`LineLayer`); a toggle to switch between the low-rise and high-rise envelope when both exist;
   - selected design: each `Floor` as an extruded slab (`SolidPolygonLayer` with 3D coordinates so the base sits at `z`, elevation `h − 0.15` to leave a visible floor line), coloured by use (parking grey, lobby/amenity sand, residential/office/hotel warm white), with a hover tooltip (floor index, use, area);
   - ground setback lines (dashed) are a nice-to-have.
   Depth must interleave with the 3D buildings (it does with interleaved mode: tested).
7. **Results panel**: (a) site summary: plot area, zone, FAR max → max floor area, OSR; (b) "Rules that apply": `AppliedRule[]` grouped by kind, each row with title, Thai title (small), value, citation (doc + clause, linked if url), muted when `applies` is false with its note; each envelope rule has an eye toggle that adds/removes its id in `SiteInput.disabledRules` (so the user can see what that rule does to the envelope); (c) envelope stats; (d) design cards (tabs or a vertical list): name, one-line summary, key metrics (GFA, FAR used vs max as a bar, height, storeys, units/rooms, parking), the checklist (`Check[]` with pass/fail/warn/info chips, required vs actual), and an expandable floor-by-floor table whose total row equals `metrics.gfa`. Selecting a card shows that design on the map. (e) `analysis.issues` shown prominently at the top when present, and `analysis.highriseBlockedReason` explained in plain English.
8. **Fixture**: `src/fixtures/mockAnalyze.ts` returning a plausible `Analysis` for any input (simple box geometry is fine) so every panel can be seen populated. Keep it obviously a mock.
9. **Feel**: Inter (Google Fonts) or system UI, 13–14 px base, tabular numbers for figures, thin 1 px dividers, restrained colour (one accent), no emojis, no gradients, units always shown (m, m², storeys). Numbers formatted with thousands separators. Empty state before a plot exists: a short "Draw your plot or pick a sample" prompt.

`npx vite build` succeeds, `npx tsc --noEmit -p .` has no errors in your files, and `npx vite` shows the shell working with the fixture: draw/edit a plot, toggle frontages, change widths and type, see panels and 3D layers update live. Final reply: files created, what works, what doesn't, anything you need from the engine or types.
